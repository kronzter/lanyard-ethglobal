# Arkiv friction log

Things that surprised us while building Lanyard on Arkiv (Rabdi testnet, `@arkiv-network/sdk`
1.0.1). Newest first. Each entry says what we tried, what happened and what we did about it.

## 2026-11-06 · B1 data layer

| #   | What we tried                                                      | What happened                                                                                                                                                                                                                          | What we did                                                                                                                            |
| --- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 12  | Transfer a readonly entity, then capture it                        | `changeOwnership` bumps `$updatedAt` (292419 → 292421) although readonly content cannot change. Our evidence schema had assumed readonly ⇒ never updated, which would have let any owner block freeze by transferring their own record | Dropped that rule; content immutability is checked by comparing captured attributes, creator and flags instead                         |
| 13  | Learn the hash of a write before its receipt                       | The SDK's `executeBatch` resolves only after the receipt, so an app killed mid-wait has no hash to reconcile                                                                                                                           | Wrap the transport and record the `eth_sendTransaction` / `eth_sendRawTransaction` result into the write journal the moment it returns |
| 14  | Date-based retention (`ExpirationTime.atDate`) for event deadlines | Works as documented on Rabdi: event end + 7 days resolved to ~1.6 M blocks, `max()` to exactly 7,884,000                                                                                                                               | Retention is computed from the event config, never from a business deadline                                                            |
| 15  | 10 `watchEntityEvents` subscriptions on one client                 | viem shares one poller across identical watchers, so 10 subscriptions cost ~26 HTTP calls/min                                                                                                                                          | One client per screen; events only trigger re-reads                                                                                    |

## 2026-11-06 · P0.6 spike (Node, keyless public RPC)

| #   | What we tried                                                      | What happened                                                                                                                                                                                                                                                                   | What we did                                                                                                                                                                 |
| --- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | An attribute named `by` (our "writer's ENS label" on every record) | `InvalidAttributeNameError`: `by` is reserved by the query language (`ORDER BY`). The reserved list is case-insensitive and also covers `and or not true false between startswith exists typeof order asc desc` and every type tag (`bool i32 u64 u256 dec bytes str addr key`) | Renamed to `by_label` in the plans and fixtures (approved plan repair, 2026-11-06). The SDK's error message is excellent; the reserved list isn't in the docs we read first |
| 2   | Deploy a contract to Rabdi (a `Faucet` for first-time gas)         | `eth_estimateGas` returns `-32603 An internal error was received`; only the `details` field says `contract creation is disabled (no-EVM Arkiv executor)`. viem's top-level message hides it                                                                                     | Funding uses a desk wallet that sends tGLM and writes a readonly `drip` record. Worth stating "no EVM / no contracts" prominently in the docs                               |
| 3   | A named schema with 32 columns                                     | `TooManyAttributesError: … got 34`: the named schema's `arkiv.schema` tag counts toward the 32-attribute limit                                                                                                                                                                  | Budget 31 columns per named schema                                                                                                                                          |
| 4   | Read back an entity's attributes                                   | The `arkiv.schema` tag appears among `$attributes` like a user column                                                                                                                                                                                                           | Capture keeps it (it is part of the immutable record); readers ignore it                                                                                                    |
| 5   | Bare `bigint` values for `u64` columns                             | Type error: a bare bigint is ambiguous between `u64` and `u256`                                                                                                                                                                                                                 | Wrap with `u64(…)`                                                                                                                                                          |
| 6   | Patch a readonly entity, extend to an earlier expiry               | Rejected at simulation with clear messages, **no transaction sent and no gas spent**                                                                                                                                                                                            | Good behaviour; our write queue can surface the message directly                                                                                                            |
| 7   | `predictEntityKeys` + `executeBatch` with cross-references         | Works exactly as documented. Keys hold only while no other create from the owner lands first; one intervening create moved every key, and the stale batch minted unrelated keys with dangling references                                                                        | Linked writes need exclusive custody; otherwise use a confirmed two-step write. The entity nonce is separate from the transaction nonce (`getEntityNonce`)                  |
| 8   | Paged reads and finality                                           | Each page reports its own `blockNumber`; pages of one query can differ. `finalized` advances in 32-block steps and lags `latest` by 65–95 blocks                                                                                                                                | No query is treated as an atomic or historical snapshot; we confirm at 96 blocks                                                                                            |
| 9   | Keyless access                                                     | Works for reads and writes from Node, with a console warning on every client creation that the public endpoint is heavily rate limited                                                                                                                                          | A read-only access key is the next step if load tests (S8) hit limits                                                                                                       |
| 10  | Expiry                                                             | No event fires at expiry, so a watcher must compare `$expiresAt` with the head itself                                                                                                                                                                                           | Our live hook sweeps expiry locally                                                                                                                                         |
| 11  | Hermes (React Native)                                              | The SDK's random entity salt throws `NoRandomSourceError` without a `crypto.getRandomValues` polyfill                                                                                                                                                                           | Polyfill pinned during the phone spike (S3)                                                                                                                                 |

Costs observed at 1 gwei: readonly create ≈ 161k gas (0.00016 tGLM), patch ≈ 48k, extend ≈ 43k,
delete ≈ 123k, a three-create batch ≈ 362k. The whole spike cost 0.0018 tGLM.
